# Interrupts

## Introduction

While executing a program, the CPU continuously follows the Fetch–Decode–Execute cycle. If it only executed instructions sequentially, it would never know when something important happened, such as a button press or a timer overflow.

One solution would be for the CPU to repeatedly check every hardware component after every instruction. However, this approach is inefficient because most of the time nothing has changed.

To solve this problem, computers use **interrupts**.

An interrupt is a signal sent by a hardware component requesting the CPU's immediate attention.

---

# Polling vs Interrupts

Before understanding interrupts, it is useful to understand **polling**.

Suppose a program wants to know if the player has pressed a button.

Without interrupts, the CPU would repeatedly check the joypad register.

```
Read Joypad

↓

Button Pressed?

↓

No

↓

Read Joypad Again

↓

No

↓

Read Joypad Again
```

This process wastes CPU time because the CPU continuously checks even when no button has been pressed.

Interrupts solve this problem.

Instead of the CPU constantly asking,

> "Has anything happened?"

the hardware simply tells the CPU,

> "Something important just happened."

The CPU can continue executing the program normally until an interrupt occurs.

---

# How Interrupts Work

The interrupt process follows a simple sequence.

```
CPU Executes Instructions

↓

Hardware Event Occurs

↓

Interrupt Requested

↓

CPU Finishes Current Instruction

↓

Interrupt is Serviced

↓

CPU Returns to Previous Program
```

This allows hardware events to be handled almost immediately without constantly checking every device.

---

# Interrupt Sources in the Game Boy

The Game Boy has five hardware interrupts.

| Interrupt | Purpose |
|-----------|---------|
| VBlank | Screen finished drawing a frame |
| LCD STAT | LCD status changes |
| Timer | Timer overflow |
| Serial | Serial communication |
| Joypad | Button press |

Each interrupt has a fixed priority and a predefined memory address called an **interrupt vector**.

---

# Interrupt Vectors

When an interrupt occurs, the CPU jumps to a specific memory location.

| Interrupt | Vector |
|-----------|--------|
| VBlank | 0x0040 |
| LCD STAT | 0x0048 |
| Timer | 0x0050 |
| Serial | 0x0058 |
| Joypad | 0x0060 |

These addresses contain routines responsible for handling each interrupt.

Once the routine finishes, execution returns to the point where it was interrupted.

---

# Interrupt Enable and Interrupt Flag Registers

The Game Boy uses two important registers to manage interrupts.

## Interrupt Enable (IE)

Address:

```
FFFF
```

This register determines which interrupts are allowed to occur.

If a bit is cleared, the corresponding interrupt is ignored.

---

## Interrupt Flag (IF)

Address:

```
FF0F
```

This register stores interrupt requests generated by hardware.

Whenever a hardware component requires CPU attention, it sets its corresponding bit inside the IF register.

An interrupt is serviced only if:

- The interrupt is requested (IF)
- The interrupt is enabled (IE)

Both conditions must be true.

---

# Interrupt Master Enable (IME)

In addition to IE and IF, the CPU contains another control mechanism called the **Interrupt Master Enable (IME)** flag.

IME acts as a global switch for all interrupts.

If IME is disabled:

- No interrupts are serviced.

If IME is enabled:

- Requested and enabled interrupts may be executed.

This allows programs to temporarily prevent interrupts while performing critical operations.

---

# Servicing an Interrupt

When the CPU decides to service an interrupt, several operations occur automatically.

1. Finish the current instruction.
2. Disable further interrupts.
3. Push the current Program Counter onto the stack.
4. Jump to the interrupt vector.
5. Execute the interrupt routine.
6. Return to the previous program.

Pushing the Program Counter ensures that execution can continue exactly where it stopped after the interrupt handler finishes.

---

# Interrupt Priority

Multiple interrupts may occur at the same time.

The Game Boy resolves this using a fixed priority order.

Highest priority:

```
VBlank

↓

LCD STAT

↓

Timer

↓

Serial

↓

Joypad
```

If two interrupts are requested simultaneously, the higher-priority interrupt is always serviced first.

---

# Returning from an Interrupt

After the interrupt routine completes, execution must continue from the interrupted program.

This is achieved using the **RETI** instruction.

Unlike a normal **RET**, RETI performs two operations:

- Restores the previous Program Counter from the stack.
- Re-enables interrupts.

Execution then continues exactly where it stopped.

---

# Why Accurate Interrupts Matter

Many Game Boy games depend heavily on interrupts.

Examples include:

- Updating graphics during VBlank
- Keeping timers synchronized
- Responding to player input
- Managing serial communication

If interrupts occur too early, too late, or in the wrong order, games may exhibit graphical glitches, incorrect timing, or unexpected behavior.

For this reason, interrupt accuracy is an essential part of emulator development.

---

# Key Takeaways

- Interrupts allow hardware to notify the CPU when attention is required.
- They eliminate the need for constant polling.
- The Game Boy supports five hardware interrupts.
- IE determines which interrupts are enabled.
- IF records which interrupts have been requested.
- IME acts as a global interrupt enable switch.
- Servicing an interrupt temporarily pauses normal program execution before returning to the original location.
- Accurate interrupt timing is necessary for correct emulation.
